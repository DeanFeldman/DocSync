# DocSync v1.10.0 manual testing

This is the Windows, Microsoft Word, migration, and installer acceptance plan for
DocSync v1.10.0. Record the tester, date, Windows and Office versions, document
names and checksums, installer checksum, screenshots, and outcome for each section.

## Test documents

Use at least two related DOCX files and one large multi-page document containing:

- headings, normal text, ordered and unordered lists, and indentation;
- repeated wording, unique wording, and long wrapped paragraphs;
- tables with multiple paragraphs per cell;
- portrait and landscape sections;
- default, first-page, even-page, and linked headers and footers;
- fields, page numbers, images, text boxes, logos, and a watermark.

Keep untouched source copies and SHA-256 checksums.

## Upgrade and migration 7

1. Copy a working pre-v1.10 workspace containing document sets, generated versions,
   history, restored versions, searches, and preview jobs.
2. Install and start v1.10.0. Confirm startup completes and a timestamped verified
   migration backup is created.
3. Confirm schema migration 7 is recorded once and the FTS virtual table and
   maintenance triggers exist when the bundled SQLite supports FTS5.
4. Confirm all sets, current heads, history, downloads, previews, and generated
   files remain available.
5. Restart and confirm no completed migration is reapplied.
6. In a disposable copy, force migration failure and confirm the original database
   is restored and passes its integrity check.

## Persistent Word worker

1. Open a large uncached document and confirm readable structured content appears
   before the Word PDF finishes.
2. Confirm Microsoft Word starts invisibly and the high-fidelity preview completes.
3. Open several uncached document versions sequentially and confirm one worker-owned
   Word process is reused.
4. Keep an unrelated interactive Word document open, close DocSync normally, and
   confirm the unrelated Word session remains open while DocSync's owned process exits.
5. Force a disposable conversion failure while a valid PDF is cached. Confirm the
   previous preview remains usable and retry succeeds after the fault is removed.
6. Restart DocSync and confirm no orphaned worker-owned Word process remains.

## Lazy page rendering and scrolling

1. Open a large multi-page document and confirm the first visible pages appear
   without waiting for every page image.
2. Inspect the render cache and confirm distant page PNGs are absent before they are
   viewed.
3. Scroll to a distant page and confirm it renders on demand.
4. Revisit that page and confirm the cached PNG is reused without timestamp change.
5. Alternate quickly between two versions and confirm stale render IDs never replace
   the active preview.
6. Exercise zoom, fit width, fit page, selectable regions, and structured fallback.

## Workspace creation, exact matching, and search

1. Create a set from large related documents and confirm progress remains responsive.
2. Verify a hash repeated only within one document does not create a cross-document
   exact group.
3. Verify wording shared by at least two documents creates the expected group and
   member counts.
4. Search for common, mixed-case, punctuation, short, missing, and repeated terms.
5. Confirm result counts and navigation match the visible current document versions.
6. Generate a new version that adds and removes search terms and exact matches;
   confirm both search and link state update.
7. Restore an older version and confirm search, exact links, preview, and history
   follow the new restored current version.

## Editing and document fidelity

1. Edit representative body, heading, list, table, header, and footer paragraphs.
2. Exercise shared wording, per-document values, and whole-paragraph override.
3. Confirm near matches still require explicit inclusion.
4. Generate new versions and inspect every output in Microsoft Word.
5. Compare text, formatting, wrapping, pagination, fields, images, tables, sections,
   and linked headers and footers against the intended result.
6. Confirm original uploads and every previous immutable version remain unchanged.

## Startup and development commands

1. With production web assets already built, run `npm.cmd start` and confirm Electron
   opens without invoking a frontend build.
2. Run `npm.cmd run dev` and confirm FastAPI, Vite, and Electron start directly.
3. Confirm the dev backend uses `.artifacts/dev-workspace` unless
   `DOCUMENTSYNC_DATA_DIR` is explicitly set.
4. Stop both modes normally and confirm their child processes exit.

## Packaging and release assets

1. Run the complete automated test gate.
2. Build and smoke-test the frozen backend.
3. Build and install `DocSync-Setup-1.10.0.exe` in a clean location.
4. Confirm the application badge, FastAPI metadata, installer properties, and audit
   records report `1.10.0`.
5. Confirm upload, reopen, add/remove document, search, download, ZIP download,
   history, restore, themes, and application restart.
6. Verify `DocSync-Setup-1.10.0.exe`, `DocSync-Setup-latest.exe`, and both entries in
   `SHA256SUMS.txt`.

## Release decision

Mark the manual gate passed only after the generated DOCX files have been inspected
in Microsoft Word, the installer has been tested from a clean location, no unrelated
Word session was terminated, and the recorded evidence above is complete.
