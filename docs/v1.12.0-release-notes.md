# DocSync v1.12.0 release notes

## Complete rendered-layout mapping

DocSync v1.12.0 substantially improves the connection between immutable Word
blocks and their rendered PDF coordinates. Generated numeric and legal prefixes,
list markers, table-of-contents page suffixes, repeated legal wording, and body
paragraphs split by automatic page numbers are resolved with contextual order
instead of being left as large gaps in the selectable layout.

When rendered header/footer text overlaps body content, the mapper now assigns
the region to the most specific supported body block. Ordinary surrounding words
still reject substring matches, so the broader mapping does not turn arbitrary
fragments into editable paragraphs.

## Blank form fields and table cells

Empty top-level table cells are now persisted as detached editor blocks rather
than disappearing because they contain no text. PyMuPDF table geometry maps
bordered empty cells, while long horizontal drawing geometry maps signature and
form underlines beside their labels. One visible underline claims one Word cell,
preventing duplicate stacked hit areas in multi-column form layouts.

Supported empty and merged top-level table cells accept text without replacing
their table, merge, borders, or surrounding cells. Empty blocks are detached by
default and therefore never become accidental exact-match targets across related
documents.

## Multiline editing

Enter and multiline plain-text paste now create Word line breaks inside the
selected block. Bold, italic, and underline formatting continue to be written at
run level. The final structural Quill newline is removed before generation while
intentional internal newlines are preserved as OOXML line breaks.

This is deliberately not structural document editing: inserting, deleting,
splitting, merging, or reordering Word paragraphs, table rows, or table columns
remains outside the safe editing boundary.

## Rendered Word layout only

The `Select from structure` control and its synthetic layout implementation have
been removed. Layout selection now comes only from regions mapped to the actual
rendered Word preview. If Word cannot prepare a preview, DocSync reports the
failure and offers a retry instead of displaying a layout that does not match the
document pages.

## Safe existing-workspace migration

Schema migration 9 additively backfills blank fields in current document
versions. It preserves all existing element and revision identities and does not
rebuild historical versions. If an older version is restored, the normal version
extraction adds its blank targets at that point.

The migration was exercised against a 408 MB real workspace containing 33
documents, 105 immutable versions, and 102,200 existing block revisions. It
completed in 18.22 seconds including the verified backup, preserved every
existing revision, added 3,744 current blank-field revisions, passed SQLite
integrity validation, and left the API health endpoint returning 200.

- TypeScript compilation and the Vite production build passed.
- The exact San Sereno acceptance document mapped all 12 visible signature
  underlines and 22 detected blank grid cells with no duplicate geometry.
- A generated DOCX retained multiline text and inline formatting inside a blank

The release workflow additionally builds and smoke-tests the frozen Windows
backend before packaging and publishing the NSIS installer.

## Known boundaries

- Word desktop is still required for the high-fidelity rendered preview.
- Unrendered, ambiguous, or low-confidence regions remain read-only.
- Nested table structures and cells containing protected drawings or embedded
  objects remain read-only in Layout editing.
- Actual paragraph, row, and column insertion/deletion remains unsupported.
- Final wrapping and pagination are authoritative only after generation and a
  fresh Word render.
