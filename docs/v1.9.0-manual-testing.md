# DocSync v1.9.0 manual testing

This is the Windows and Microsoft Word acceptance gate for DocSync v1.9.0.
Automated tests do not replace it. Record the tester, date, Windows version,
Office version/build, test-document names, screenshots, generated DOCX files, and
result for every section.

## Test documents

Prepare at least two related DOCX files, including one large document, with:

- headings, normal paragraphs, ordered and bullet lists;
- repeated wording and long wrapped paragraphs;
- tables with multiple paragraphs in a cell;
- multiple sections, including portrait and landscape pages;
- default, first-page, even-page, and linked headers and footers;
- fields, page numbers, images, logos, a text box, and a watermark.

Keep untouched source copies and SHA-256 checksums.

## Upgrade and migration

1. Start with a copy of a working v1.8 workspace containing saved sets, generated
   versions, history, and preview jobs.
2. Install and start v1.9.0. Confirm startup completes and the existing sets open.
3. Confirm a verified timestamped migration backup was created before schema 6.
4. Confirm current versions, history, downloads, block mappings, and prior generated
   files remain available.
5. Restart DocSync and confirm migration 6 is not reapplied.

## Progressive document opening

1. Open a large uncached document. Confirm readable structured content appears
   before the complete high-fidelity Word preview.
2. Confirm the Word preview begins automatically without a **Load Word Preview**
   action.
3. Confirm page images appear progressively and nearby pages load while scrolling.
4. Reopen the same immutable version. Confirm the cached content appears promptly
   and no unnecessary Word startup occurs.
5. Open a different version and confirm it does not reuse the first version's
   preview.
6. Alternate rapidly between two large documents. Confirm late responses never
   replace the active document and duplicate preview work is not started.

## Workspace layout and scrolling

1. Maximize, restore, and resize the DocSync window at desktop and narrow widths.
2. Confirm the workspace fills the remaining window height without unused space
   below the preview.
3. Confirm the outer application page does not scroll while a workspace is open.
4. Confirm the file rail, Word preview, and operation sidebar scroll independently.
5. Confirm zoom, fit width, fit page, selectable areas, structure fallback, and
   preview retry remain usable at each tested size.

## Processing UI

1. Confirm there is no global **Processing** or **Recent processing** button.
2. Confirm no processing-history popover or global retry control appears.
3. Queue a version generation and continue navigating. Confirm progress remains
   inline with the active operation.
4. Restart during a disposable test operation. Confirm no floating **Processing
   interrupted** notification appears after restart.
5. Cause a safe preview or generation failure. Confirm the error is inline, does not
   block unrelated navigation, and no floating processing popup appears.

## Inline editing and generation

1. Select and edit body, heading, list, table, header, and footer paragraphs.
2. Confirm Quill loads on the first editable selection and the cursor, formatting,
   Undo/Redo, Escape, keyboard selection, and one-paragraph restrictions work.
3. Review exact matches and near-match differences. Confirm near matches require
   explicit inclusion.
4. Exercise shared wording, per-document values, and whole-paragraph override.
5. Preview every intended document and location.
6. Double-click **Generate new versions**. Confirm only one job is accepted and the
   button remains disabled while it is pending.
7. Confirm only affected documents refresh and every result receives a new immutable
   version and preview.
8. Open the generated files in Word and verify content, formatting, wrapping,
   pagination, fields, images, tables, sections, and linked headers/footers.

## Cache failure and recovery

1. With a valid cached preview, force Word conversion to fail in a disposable
   development workspace.
2. Confirm the previous cached content remains visible and an inline error explains
   the failed refresh.
3. Resolve the Word failure and use **Retry preview**. Confirm the cache and layout
   refresh successfully.
4. Externally modify a disposable source file at the same path. Confirm source
   identity invalidates the cache and prevents stale content from being treated as
   fresh.

## Regression and packaging

1. Verify upload, reopen, add/remove document, search, download, ZIP download,
   version history, restore, theme switching, and application restart.
2. Repeat representative workflows in light and dark themes using mouse and
   keyboard navigation.
3. Build the frozen backend and run its packaged health smoke test.
4. Build and install `DocSync-Setup-1.9.0.exe` in a clean location.
5. Confirm the application badge, FastAPI metadata, installer properties, and audit
   records report `1.9.0`.
6. Verify `DocSync-Setup-1.9.0.exe`, `DocSync-Setup-latest.exe`, and
   `SHA256SUMS.txt`, including both SHA-256 entries.

## Release decision

The release may be marked passed only when the automated release workflow succeeds,
the generated DOCX files have been inspected in Microsoft Word, the installer has
been tested from a clean location, and all evidence above has been recorded.
