# DocSync v1.7.0 release notes

Released: 4 August 2026

DocSync v1.7.0 adds safe Microsoft Word header and footer paragraph editing and
restores the project documentation for versions 1.5, 1.6, and 1.7.

## Header and footer blocks

- Extracts default, first-page, and even-page headers and footers across every
  Word section.
- Represents each mapped paragraph as `header_paragraph` or
  `footer_paragraph` with section, part type, paragraph, relationship, and
  document-order metadata.
- Detects inherited **Link to Previous** relationships.
- Deduplicates sections that use the same physical header/footer part, so one
  Word paragraph cannot appear as duplicate edit targets.
- Groups headers, body content, and footers in structured Layout and Edit and
  provides keyboard selection and explicit selected/read-only labels.

## Safe editing and preservation

- Supports bold, italic, underline, alignment, indentation, and Word lists in
  safely mapped header/footer paragraphs.
- Retains the one-paragraph Quill boundary: Enter cannot add a block and
  multiline paste is flattened.
- Revalidates section, type, physical relationship, and paragraph index against
  the exact immutable source version immediately before write-back.
- Preserves sibling paragraphs, section settings, link relationships, margins,
  tables, images, logos, and unrelated formatting.
- Paragraphs containing fields, drawings, shapes, embedded objects, content
  controls, tracked changes, or comments remain visible and read-only with a
  reason.

## Matching, search, and processing

- Exact and near matching include header/footer paragraphs but require the same
  block type, header/footer type, and source-section context.
- Identical body text cannot become an automatic header/footer target.
- Global search results include section, part type, and paragraph metadata.
- Preview reports linked sections and the exact header/footer location.
- Processing uses the v1.6 background-job, conflict, atomicity, selective
  refresh, active-draft, immutable-history, and restoration boundaries.

## Migration

Schema migration 4, `header_footer_paragraph_foundation`, reparses every stored
immutable DOCX and rebuilds its block revisions from OOXML. Shared physical
parts are deduplicated. The ordered migration framework creates and verifies a
timestamped SQLite backup first and restores it automatically on failure.
