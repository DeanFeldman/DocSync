# DocSync v1.8.0 inline-layout editing requirements

Status: implemented specification baseline, 4 August 2026.

This document records the v1.8.0 contract implemented from the supplied
“Inline Editing in the Word Layout Preview” specification. It supersedes the
earlier read-only/direct-selection wording for v1.8 without removing structured
Edit as the safety fallback.

## Preview processing (FR-01–FR-08)

- **Load Word Preview** creates a durable, immutable-version-bound job and
  returns `202 Accepted` without waiting for Word.
- One local worker serializes Word exports. Jobs persist status, stage,
  independent `pdf_ready` and `render_map_ready` flags, timestamps, cache use,
  and an error.
- Stages cover queued, starting Word, opening, PDF rendering, display,
  selectable-text preparation, ready, and failed states.
- A complete cached PDF for the exact version bypasses Word. A different
  version always has a different cache key.
- PDF availability does not wait for mapping. Failure leaves structured Layout
  and Edit usable and permits a new retry job.

## Controlled preview and mapping (FR-09–FR-24)

- Native PDF iframes are not used by the v1.8 controlled viewer. PyMuPDF emits
  page images and dimensions; visible and nearby pages are mounted first.
- Controls include zoom in/out, zoom level, fit width, fit page, persistent
  selectable areas, structure fallback, and retry.
- Regions use normalized `0..1` coordinates and include immutable version,
  render, element, page, confidence, method, interaction, read-only, and reason
  metadata. Wrapped and cross-page paragraphs may have several regions.
- Mapping uses normalized text, element type, header/footer context, document
  order, page position, and immutable version identity. Repeated or overlapping
  candidates are interactive only when resolved safely.
- The default interactive confidence threshold is `0.90`. Ambiguity degrades to
  no inline editor. Zoom and resize alignment comes from page-relative HTML
  positioning inside the scaled page surface.

## Inline editor (FR-25–FR-35)

- Activating an interactive region keeps Layout active, selects the exact
  current-version `element_id`, overlays a restricted Quill editor, and places
  the caret proportionally near the clicked line/position.
- The editor loads the versioned Delta and visually covers the snapshot text.
  Enter is rejected and multiline paste is flattened, preventing structural
  insertion, splitting, or merging.
- Layout and structured Edit share one draft. A block change with uncommitted
  draft or per-document values opens the existing keep/discard dialog.
- Each block activation creates a new Quill history. Undo and Redo apply to the
  active inline block. Escape closes inline typing and restores region focus;
  Tab, Enter, and Space provide keyboard region activation.

## Operation sidebar (FR-36–FR-43)

- Layout reuses the current editor operation state and backend validation.
- The sidebar reports document, version, block type, location, and linked
  header/footer context; exposes bold, italic, underline, headings where valid,
  lists, indentation, alignment, Undo, and Redo; and displays exact targets.
- Near matches show score and word differences and require an explicit
  include/exclude decision. Shared, per-document, and whole-paragraph modes use
  the existing preview and non-blocking generation endpoints.

## Fixed-snapshot behavior (FR-44–FR-48)

- Layout labels edits as draft layout and never claims browser repagination.
- Materially longer text produces a wrap warning.
- Successful generation atomically advances immutable heads and queues a new
  preview and render map. An active safe Layout view follows the new version;
  an unrelated dirty draft keeps the existing newer-version choice.

## Read-only and fallback behavior (FR-49–FR-56)

Fields, images, drawings, text boxes, watermarks, embedded objects, content
controls, tracked changes, comments, unsafe hyperlinks, and unsupported nested
tables remain preserved and read-only. Reliably located read-only areas expose
a reason and never mount an editor. Missing coordinates use **Select from
structure** and structured Edit.

## API and data contract (FR-57–FR-60)

```text
POST /api/document-versions/{version_id}/preview-jobs
GET  /api/preview-jobs/{job_id}
GET  /api/document-versions/{version_id}/preview
GET  /api/document-versions/{version_id}/render-map
GET  /api/document-versions/{version_id}/render-pages/{render_id}/{page}.png
```

`PreviewRenderJob` is persisted in schema 5. PDF and JSON/page-image caches are
stored by immutable version and validated with source/PDF identity. Existing
document head and operation validation rejects stale edits before preview or
generation.

## Safety and performance

- Original uploads are never overwritten; successful writes create immutable
  versions and multi-document head advancement remains atomic.
- Word export is single-worker; render mapping is a separate bounded executor.
- Hover/focus feedback is CSS-local, and page mounting uses
  `IntersectionObserver` with a nearby-page margin.
- The PDF is a temporary visual/selection surface and is never modified.
