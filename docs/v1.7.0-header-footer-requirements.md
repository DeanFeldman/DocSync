# DocSync v1.7.0 header and footer requirements

Prepared by Dean Feldman (student number 2803899) on 4 August 2026.

## Objective and scope

Version 1.7.0 adds safe structured editing for default, first-page, and
even-page headers and footers in multi-section DOCX files. It includes
selection, rich-text editing, exact and near matching, shared/per-document
changes, search, preview, background processing, immutable versions,
restoration, schema migration 4, and restored README history.

It does not add or delete sections, headers, footers, or paragraphs; change
section breaks, margins, odd/even or first-page settings; create or break Link
to Previous; edit Word fields; or edit/move watermarks, shapes, text boxes,
images, logos, and nested header/footer tables. Unsupported content must remain
preserved and read-only.

## Structured blocks

Every Word section receives a zero-based `section_index`. The extractor inspects
these part types:

```text
default_header       default_footer
first_page_header    first_page_footer
even_page_header     even_page_footer
```

Each non-empty supported paragraph is a separate `header_paragraph` or
`footer_paragraph`. Paragraphs containing unsafe visible objects are also
represented as read-only diagnostics. Each immutable revision stores:

```json
{
  "kind": "header_paragraph",
  "section_index": 0,
  "header_footer_type": "default_header",
  "paragraph_index": 1,
  "part_relationship_id": "rId8",
  "document_order": 3,
  "is_linked_to_previous": true,
  "source_section_index": 0,
  "linked_sections": [0, 1]
}
```

Locations are regenerated from each immutable DOCX and are never silently
reused across versions. If multiple sections resolve to the same physical part,
one physical paragraph produces one block and metadata lists every affected
section.

## User experience

Structured Layout and Edit group headers, body blocks, and footers separately.
Labels identify region, one-based section, default/first/even context, and
paragraph. Linked content explains all affected sections before processing.
Cards are operable with Enter and Space, and selection/read-only state uses
text as well as colour.

A supported selection opens Edit, selects the exact immutable block, loads its
Delta, shows section context, and focuses Quill. Bold, italic, underline,
alignment, lists, and indentation are supported. Enter, paragraph insertion,
deletion, split, merge, reorder, and multiline paste remain structurally
blocked.

## Preservation boundary

The writer must resolve and validate the source section, header/footer type,
physical relationship, and paragraph index before mutation. Editing must
preserve sibling paragraphs, fields, logos, images, tables, section settings,
distances, margins, link relationships, unsupported objects, and unselected
content.

Paragraphs that contain PAGE/NUMPAGES/date/file/author/document-property or
other complex fields, drawings, pictures, shapes, text boxes, watermarks,
embedded objects, content controls, tracked changes, or comments are read-only
where safe partial rewriting cannot be guaranteed.

## Matching, search, and API

Exact identity includes normalised text, block type, header/footer type,
source-section context, and the immutable revision. Near matches show a score
and word differences and always require confirmation. Search includes header
and footer text and returns enough metadata to reopen the precise immutable
block.

Existing editor-content, matches, similar-matches, compare, match-decisions,
editor-preview, asynchronous generation, operation-status, and search APIs must
accept the new block types. Preview reports document, source version, section,
part type, paragraph, linked sections, before/after values, and edit mode.

## Processing and version safety

Process returns control quickly and runs through the v1.6 durable background
job. Navigation and unrelated drafts remain available. Completion selectively
refreshes affected heads, history, blocks, matches, search, downloads, and job
status. A newer version cannot silently replace an unrelated draft.

Base-version drift returns `409 Conflict`. A multi-document change commits as
one atomic operation or advances no head. Original uploads are immutable,
successful output creates new immutable versions, and earlier versions remain
downloadable and restorable.

## Migration and quality gates

Ordered schema migration 4 is named
`header_footer_paragraph_foundation`. Before it runs, the migration coordinator
creates a timestamped SQLite backup and verifies integrity. The migration
reparses every stored immutable DOCX, caches part/paragraph/style data per file,
deduplicates physical parts, rebuilds historical revisions, and restores the
original database if any step fails.

Automated tests cover all six part types, multiple sections/paragraphs, link
detection and deduplication, mapping, matching, search, write-back, fields,
images, conflicts, rollback, migration, background jobs, UI context,
accessibility, draft protection, and light/dark styling. Manual Word fixtures
also cover fields, logo, watermark, footer table, and visual source/output
comparison on supported Windows and Word versions.
