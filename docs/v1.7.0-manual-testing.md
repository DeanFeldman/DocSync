# DocSync v1.7.0 manual testing

Use Windows 10 and Windows 11 with a supported desktop Microsoft Word version.
Keep the source fixtures unchanged and record the DocSync build, Word version,
Windows version, tester, date, and result for each run.

## Fixtures

Prepare two related DOCX files containing:

- two sections, with section 2 linked to the previous default header;
- default header and footer;
- first-page header and footer;
- even-page header and footer;
- at least two direct paragraphs in a header and footer;
- PAGE and NUMPAGES fields and a DATE or DOCPROPERTY field;
- a company logo, watermark, shape/text box, and small footer table;
- exact repeated header/footer wording in both files;
- similar but non-identical header/footer wording;
- body text identical to one header string.

## Extraction and selection

1. Create a document set from the fixtures.
2. Confirm all supported header/footer paragraphs appear once with correct
   Header/Footer, section, default/first/even, and paragraph labels.
3. Confirm the linked section does not create a duplicate block and the card
   lists both affected sections.
4. Confirm header, body, and footer groups are distinct in Layout and Edit.
5. Select a supported block with mouse, Enter, and Space. Confirm Edit opens,
   the exact block is selected, context is shown, and Quill receives focus.
6. Search for header/footer text and confirm selection reopens the right file,
   version, section, part type, and paragraph.

## Editing and comparison

1. Apply bold, italic, underline, alignment, indentation, and both list types to
   supported fixture paragraphs.
2. Confirm Enter does not create a paragraph and multiline paste becomes one
   paragraph.
3. Confirm exact results include only compatible header/footer context and not
   identical body text.
4. Confirm a near match shows score and word differences and is excluded until
   explicitly confirmed.
5. Exercise shared wording, per-document value, and one-paragraph override.
6. Confirm preview lists source version, section, type, paragraph, linked
   sections, mode, and before/after text.

## Read-only and preservation checks

1. Confirm field, logo, watermark, shape/text-box, and content-control
   paragraphs are visible as read-only with a reason.
2. Process an edit in a safe paragraph beside every unsupported object.
3. Open the generated DOCX in Word and update fields.
4. Compare source and output visually: PAGE/NUMPAGES/date/property fields,
   logo, watermark, shape/text box, footer table, margins, header/footer
   distances, section breaks, first/even settings, and Link to Previous must be
   unchanged.
5. Confirm sibling paragraph text and formatting are unchanged.

## Background, conflicts, and history

1. Select Process and confirm control returns promptly while the job indicator
   progresses through queued, preparing, applying, validating, saving, and
   refreshing.
2. Navigate to another document and edit a draft. Confirm completion does not
   replace it and the newer-version choice is shown when applicable.
3. Confirm success/failure notifications are non-blocking.
4. Preview an edit, change the same document in another operation, then process
   the stale preview. Expect `409 Conflict`, no partial version, and unchanged
   heads.
5. Force a write/validation failure in a disposable workspace. Confirm every
   head remains unchanged, output is removed, and the job is failed.
6. Download the new version, restore the previous version, and confirm both
   remain in immutable history.

## Migration and themes

1. Copy representative v1.4, v1.5, and v1.6 workspaces before testing.
2. Start v1.7 and confirm a verified timestamped migration backup exists,
   schema version is 4, historical versions expose header/footer blocks, and
   current content remains intact.
3. In a disposable copy, force migration failure and confirm the original
   database is restored automatically.
4. Repeat block, link, selected, read-only, preview, job, and notification
   checks in light and dark themes.

The release passes only after every generated file opens without repair prompts
and its Word visual comparison is signed off.
