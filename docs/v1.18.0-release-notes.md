# DocSync v1.18.0

## Account-local workspaces

DocSync now keeps each authenticated account's local work in its own
account-scoped workspace. Signing out blocks the document workspace and stops
its backend; signing into another account starts a fresh backend session against
that account's directory. Existing pre-account workspaces are detected and may
be copied into an account workspace without deleting the source.

## Cloud backups and restore

Authenticated users can create private, immutable workspace snapshots and back
them up through the configured Supabase provider. A backup is hashed, uploaded,
verified, and atomically promoted before it is reported as synced. A new
computer can discover the latest backup and restore it through the same staged,
validated rollback-safe snapshot engine.

DocSync remains local-first: local work is still usable while cloud services are
offline. A newer cloud revision never silently overwrites dirty local work;
DocSync reports a conflict and preserves the local workspace for recovery.

## Accounts and sign-in

The account control now shows the active profile, sign-out action, cloud status,
and the Admin foundation for trusted admin roles. The Google sign-in return now
uses an HTTPS completion page with an automatic and manual **Open DocSync**
deep-link option. PKCE exchange and tokens remain in the desktop app.

## Upgrade notes

v1.18 does not upload document contents until a user initiates or allows a cloud
backup. Configure the private Supabase Storage bucket, RLS policies, completion
edge function, and public release-build variables before distributing an
installer. See the v1.18 Supabase checklist and manual test guide.
