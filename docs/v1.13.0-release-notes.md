# DocSync v1.13.0 release notes

## Pending Changes in Layout

Direct Layout edits now stage automatically into one durable Pending Changes
batch. The editor retains the staged value when a block is reopened, and a
read-only pending overlay displays every staged direct replacement over the
immutable Word/PDF preview. The overlay is removed when its operation is
removed, cleared, or applied; it never generates a DOCX merely for display.

Preview All remains side-effect free and shows base Word text as **before** and
the pending replacement as **after**. Applying the reviewed batch remains the
only step that creates immutable document versions.

## Safer form-line mapping

Qualified blank body paragraphs with a Word paragraph border or underlined,
tab-only form structure are preserved as editable targets. Their rendered line
geometry can be mapped below labels and across stacked signature fields. Each
line maps to at most one real Word target; plain blank spacers and ambiguous
decorative rules stay unmapped.

Render-map caches use schema version 5 and include concise diagnostic counts
for detected lines, qualified blank candidates, and matched form lines.

## Appearance preference

Appearance offers System, Light, and Dark choices. The desktop bridge stores
the preference in Electron user data, so it survives restart even when the
local backend uses a different port.

## Verification

- Focused pending-batch, Layout-overlay, and render-map contract tests passed.
- Batch-editing and full inline-preview regression suites passed.
- TypeScript compilation, Vite production build, and diff checks passed.

## Known boundaries

- Pending overlays are a working-view preview; final Word wrapping and
  pagination require Preview All and generation.
- Find & Replace occurrences retain their existing batch review experience;
  the Layout overlay targets direct editor operations.
- Bare PDF drawing lines without a qualified writable Word paragraph remain
  read-only/unmapped.
