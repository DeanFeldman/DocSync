# DocSync v1.9.0 release notes

## Faster document opening

DocSync v1.9.0 makes useful document content visible before Microsoft Word
finishes high-fidelity conversion and selectable-area mapping.

- Added a durable SQLite preview cache keyed by immutable document version.
- Validates cached content against source checksum, byte size, modification time,
  PDF size, and PDF modification time.
- Shows cached or structured content first and refreshes the Word layout in the
  background.
- Keeps a stale but usable preview visible when a refresh is required or fails.
- Deduplicates in-memory requests, preview jobs, Quill imports, and overlapping
  document-selection effects.
- Loads the first two page images eagerly and nearby pages on approach.
- Loads Quill and its Snow CSS only after an editable region is selected.

In the release benchmark, a cached 1,000-block structured preview returned in a
26.98 ms median. Cold Word conversion remains dependent on Microsoft Word startup,
document complexity, fonts, images, and COM automation.

## Faster version generation

- Reads each affected DOCX once and builds reusable paragraph, table,
  header/footer, and style indexes.
- Applies edits and validates the generated package without repeated full parses.
- Retains stable `DocumentElement` identities for unchanged locations.
- Rebuilds only exact-match hashes whose membership changed.
- Batches database inserts and defers preview work until immutable versions commit.
- Stores already-compressed DOCX packages in the output ZIP without recompressing
  them.
- Rejects overlapping submissions before expensive validation and returns only the
  changed document rows needed for asynchronous reconciliation.

The measured three-document, 300-block-per-document generation median improved
from 782.75 ms to 523.78 ms, a 33.1% reduction.

## Focused workspace UI

- The workspace fills the desktop window and locks the outer application page to
  the viewport.
- Document, file-list, and sidebar scrolling remain inside their own regions.
- Removed the global **Processing** button, processing-history popover, retry
  control, and floating processing notifications.
- Durable generation continues in the background, with relevant progress and
  actionable errors kept inline with the active document.
- Removed unreachable legacy viewer/editor code and the obsolete
  `QuillBlockEditor` implementation.

## Safety and compatibility

- Original uploads and previous immutable versions remain unchanged.
- Failed generation still rolls back database changes and staged files.
- Cached-preview failures preserve the previous usable payload where available.
- Request IDs, abort controllers, active-document checks, version-keyed resource
  keys, shared in-flight promises, and backend active-job checks prevent stale work
  from replacing the selected document.
- Existing Delta data remains compatible; Quill is still the active restricted
  editor and has not been removed as a dependency.

## Upgrade and storage

Schema migration 6, `durable_document_preview_cache`, adds the
`document_preview_cache` table and `stale_preview_available` preview-job field.
Existing workspaces are backed up and integrity-checked before the migration runs.
No manual SQL or cache conversion is required.

PDF and page-image files remain in the render directories. SQLite stores structured
and Word-preview JSON plus source/PDF identity, avoiding duplicate binary storage.

## Diagnostics and verification

Backend and frontend timing events now cover document fetch, Word rendering, DOCX
conversion, render-map work, generation queueing, per-document generation, preview
rendering, document readiness, Quill import, and editor initialization. Relevant
fetch endpoints also expose `Server-Timing` and `X-DocSync-Preview-Cache` headers.

The automated release gate includes backend tests, desktop/frontend contract tests,
TypeScript compilation, the production Vite build, the frozen Windows backend build,
its health smoke test, and installer packaging. Real Microsoft Word behavior remains
a separate acceptance gate documented in
[the v1.9.0 manual test plan](v1.9.0-manual-testing.md).

Detailed benchmark methodology and implementation notes are available in the
[document performance report](performance-optimisation-2026-08.md).
