# DocSync v1.8.0 preview-overlay requirements

**Release:** DocSync v1.8.0 - Direct Selection in Word Preview  
**Prepared by:** Dean Feldman  
**Student number:** 2803899  
**Date:** 4 August 2026

## Goal and safety rule

Users can select supported text directly from the high-fidelity Word preview
and open the exact corresponding immutable structured block. The preview is a
selection surface only: typing, moving, resizing, splitting, deleting,
reordering, or editing Word objects inside the PDF is out of scope.

DocSync must prefer no interactive overlay over an incorrect mapping. Original
uploads remain immutable, unsupported structures remain read-only, and all
changes continue through structured preview and versioned generation.

## Required content and interaction

Direct selection covers supported headings, body paragraphs, ordered and
unordered list items, table paragraphs, header paragraphs, and footer
paragraphs across multiple pages and sections. One block may own several line-
or page-level regions. Selecting any region opens the same block.

The existing structured Layout surface remains available at all times. When
Word/PDF rendering fails it loads normally and no coordinate work is requested.
When mapping is partial or fails, the PDF remains visible and unmapped content
has no clickable target.

An editable overlay activation must:

1. Carry the immutable `version_id` and `element_id`.
2. Verify the displayed map version in the client.
3. Resolve the element in the current version-scoped editor content.
4. Verify document ownership and supported/read-only state.
5. Run normal unsaved-draft protection.
6. Open Edit, select the exact block, load its Delta and location, and focus
   Quill.

Linked header/footer regions open the deduplicated physical-part block. Table
regions retain table, row, column, and in-cell paragraph indexes.

## Render-map contract

Every map is bound to the immutable document/version, source DOCX SHA-256, exact
PDF SHA-256, PDF engine, mapper engine/version, page count, and render ID. It is
invalid when any of those identities or the PDF fingerprint changes.

The endpoint is:

```text
GET /api/document-versions/{version_id}/render-map
```

Statuses are:

```text
not_requested queued processing completed partial failed
```

Each page records a stable page/render identifier, page number, width, height,
normalised coordinate unit, render version, image dimensions, and validated
page-image URL. Each region records:

```text
region_id, element_id, document_id, version_id, element_type
page_number, x, y, width, height
confidence, mapping_method, interactive, editable, supported, read_only, reason
location, text_preview
```

Coordinates are finite normalised numbers between zero and one with at least
six decimal places. Separate line rectangles are preferred over one rectangle
that would overlap unrelated content.

## Confidence and ambiguity

Every mapped region has a confidence from 0 to 1. The default interactive
threshold is 0.90 and is configurable. Unsupported blocks never become
editable even at high confidence.

Contextual matching may use text, full line boundaries, document order,
neighbouring sequence, page position, element type, table/header/footer
location, section/header variant, and formatting. Text alone is not sufficient
when more than one block or region could match. Duplicate cardinality and
document order may resolve a one-to-one sequence; unresolved or overlapping
candidates remain non-interactive.

## Overlay and viewer requirements

HTML overlays are positioned inside the exact page-image box using percentages.
They move with the page and remain aligned during:

- zoom in and out;
- fit width and fit page;
- window and sidebar resizing;
- vertical and horizontal scrolling.

Rotation is not offered while direct selection is active. Overlays do not
permanently obscure text. Editable hover/focus uses a visible teal outline;
selected regions use a stronger persistent state; read-only regions use a
distinct non-editable treatment. **Show selectable areas** reveals subtle
outlines for all mapped regions.

The toolbar exposes Zoom out, zoom level, Zoom in, Fit width, Fit page, Show
selectable areas, and Select from structure. The Word PDF appears before
background mapping completes. Visible and nearby pages are prioritised so large
documents do not mount all images and regions at once.

## Accessibility

Editable and read-only overlays are focusable in page/document order with Tab
and Shift+Tab. Enter and Space activate an editable overlay. Each region has a
visible non-colour-only focus outline and an accessible label containing type,
page, location, short text, and editable/read-only state. States and controls
remain legible in light and dark themes.

## Failure and security requirements

- A successful Word PDF is independent from coordinate extraction success.
- Invalid PDFs, excessive page counts, invalid dimensions, bad coordinates,
  missing files, or mapper errors produce a safe failed status.
- Map/page endpoints resolve the immutable version on the backend and reject a
  render ID or page that does not belong to it.
- A stale overlay cannot open a newer/different version; the existing editor
  path refreshes instead.
- Render files are private local cache artifacts and are served only through
  validated endpoints.

## Acceptance criteria

Acceptance requires aligned direct selection for supported body, list, table,
header, and footer fixtures; correct selection after zoom/resize/scroll;
rejection of ambiguity and low confidence; read-only preservation; keyboard
operation; PDF and structured fallback on mapping failure; immutable cache
invalidation; passing automated tests; passing the manual Word/PDF plan; a
smoke-tested Windows installer; complete documentation; and an authorised
`v1.8.0` release tag.

The implementation and automated evidence are documented in
[the release notes](v1.8.0-release-notes.md). Manual acceptance is defined in
[the manual test plan](v1.8.0-manual-testing.md).
