# DocSync v1.18 cloud foundation setup

Run the Phase 2 SQL first, then run `analytics/supabase-v1.18-cloud-schema.sql` in the Supabase SQL Editor. It creates the private `docsync-workspaces` bucket, device/snapshot/head tables, RLS policies, and the ownership-checked promotion RPC. Confirm the bucket is private in Storage, then test with two ordinary accounts: each account can create/list only `users/<its-uuid>/snapshots/<snapshot-uuid>.zip`; neither can list or download the other's objects or rows.

The installed app uses only `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. Do not add a service-role or secret key to GitHub variables consumed by Vite, Electron, or the Python backend. v1.18 uses this provider for account-scoped snapshot upload, verification, atomic promotion, discovery, and staged restore; it does not expose workspace archives to administrators or other accounts.
