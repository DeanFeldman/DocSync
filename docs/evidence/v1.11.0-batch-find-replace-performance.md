# Batch Find & Replace performance evidence

Measured on 24 August 2026 in the local Windows development environment with:

```powershell
python apps/api/scripts/benchmark_batch_find_replace.py --runs 3
```

## Exhaustive Find scanner

Synthetic workload: 50 documents × 1,000 logical segments = 50,000 segments,
with 500 exact occurrences. FTS5 trigram candidates only order the complete
authoritative scan.

| Measurement | Median |
| --- | ---: |
| FTS5 candidate retrieval | 1.37 ms |
| Exact logical occurrence scan/result construction | 810.71 ms |
| Total result build | 811.98 ms |

## Replacement-plan compilation

| Occurrences | Median | Compiled OOXML nodes |
| ---: | ---: | ---: |
| 100 | 0.15 ms | 100 |
| 500 | 0.84 ms | 500 |
| 1,000 | 1.42 ms | 1,000 |
| 5,000 | 9.05 ms | 5,000 |

## Batched package passes

Workload: 10 DOCX packages × 10 independent edits/document.

| Strategy | Package scan/write passes | Median |
| --- | ---: | ---: |
| One compiled batch/document | 10 | 119.97 ms |
| Repeated one-edit regeneration | 100 | 1,178.87 ms |

Measured speed-up: **9.83×** for the package scan/patch/write boundary. This
benchmark intentionally isolates the architecture's repeated-package cost; it
does not claim Microsoft Word preview, database commit, or full Electron UI
latency.
