# DocSync v1.4.1 performance evidence

Date: 28 July 2026  
Platform: local Windows reference environment  
Python: 3.14.2  
Baseline source: `26b3f199bb637511918121eae4480b3302dc126d`

## Dataset and method

The benchmark uses the v1.4.1 Standard profile:

- 10 DOCX documents
- 500 structured blocks per document
- 3 sequential creation runs per implementation
- Identical generated DOCX payloads and benchmark harness
- Separate temporary SQLite/data directories for the baseline and v1.4.1
- HTTP timing measured around `POST /api/document-sets`
- Microsoft Word rendering excluded, as required for document-set creation

Commands:

```powershell
python apps/api/scripts/benchmark_workspace_loading.py `
  --documents 10 --blocks 500 --runs 3 `
  --api-dir .tmp/v140-source/apps/api

python apps/api/scripts/benchmark_workspace_loading.py `
  --documents 10 --blocks 500 --runs 3 `
  --baseline-ms 31435.11
```

The baseline directory was an unmodified archive of the commit shown above.

## Results

| Implementation | Run 1 | Run 2 | Run 3 | Median | p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Pre-change baseline | 31,435 ms | 34,844 ms | 27,086 ms | 31,435 ms | 34,844 ms |
| v1.4.1 | 2,102 ms | 3,288 ms | 3,191 ms | 3,191 ms | 3,288 ms |

Median improvement:

```text
(31,435.11 - 3,190.67) / 31,435.11 = 89.85% faster
```

Result: **PASS**. The measured improvement exceeds the required 40% target.

| --- | ---: |
| Upload read | 0.15 ms |

| Parsing and extraction | 230.30 ms |
| Structured editor preparation and persistence | 2,074.25 ms |
| Exact-match setup | 832.14 ms |
| Response serialization | 0.07 ms |
| Server total | 3,177.64 ms |

## Main measured changes

- Each DOCX package is validated once and parsed once.
- The parsed document, paragraph list, table list, and style-name map are reused.
- Paragraph style resolution is no longer repeated for every editor block.
- New elements, immutable versions, heads, and block revisions are assembled
  and flushed in batches.
- The create response performs no Word/PDF rendering.

The benchmark JSON files are generated artifacts and are intentionally not
committed. Re-run the commands above on the release machine before publishing
