# DocSync v1.4.0 release notes

DocSync v1.4.0 makes the Layout workspace actionable and adds a persistent dark
theme without weakening the editor's document-mapping safety.

## Direct Layout selection

- Supported headings, paragraphs, list items, and mapped top-level table cells
  are selectable in the structured Layout view.
- A Layout selection is resolved by stable `element_id` against the current
  `document_id` and `version_id`.
- Successful selection switches to Edit, loads the block Delta, enables Quill,
  and restores focus.
- Selecting the active block again preserves its draft and restores focus.
- Selecting another block with an unpreviewed draft uses the existing
  OK/Cancel confirmation workflow.
- Unsupported or preserved Word structures remain visible and read-only with an
  explanatory reason.
- Search, Layout, and Edit selections share the same selection and recovery
  path.

The API now exposes an optional `layout_regions` collection for future
page-relative overlays. The current Word/PDF renderer does not provide bounds
that are reliable enough for safe write-back, so it returns an empty collection.
The rendered preview therefore stays read-only and the UI offers the selectable
structured document instead of guessing coordinates.

## Dark theme

- A visible light/dark button is available in the application header.
- The control is keyboard accessible and reports its pressed state.
- Explicit preference is stored under `docsync-theme`.
- With no saved preference, DocSync follows `prefers-color-scheme`.
- Theme is applied before React starts to prevent a light startup flash.
- Invalid or unavailable storage falls back safely.
- The workspace, dialogs, search, comparison UI, Quill editor, toolbars, forms,
  notices, and read-only states have dark-theme coverage.
- Word/PDF and structured document canvases remain white paper surfaces for
  document fidelity and readability.
- Switching theme does not remount Quill or reset active document, workspace
  mode, selection, draft, comparison, preview, scroll, or dialog state.

## Compatibility and safety

- Original DOCX files remain immutable.
- Preview-before-generation, stale-version checks, version history, restoration,
  and atomic generation behavior are unchanged.
- Error banners remain dismissible and informational; they do not disable or
  cover the editor.
- The structured Layout fallback remains available when Microsoft Word rendering
  is unavailable.

## Acceptance checks

- Select a supported paragraph, heading, list item, and mapped table cell from
  Layout and confirm the correct block opens focused in Edit.
- Confirm unsupported elements cannot be edited and show a reason.
- Confirm OK and Cancel both leave the editor usable when a draft exists.
- Toggle light/dark mode with a draft and comparison state present; confirm no
  state is lost.
- Restart the application and confirm an explicit theme preference is restored.
- Remove the saved preference and confirm the Windows/system color preference is
  used.
- Run `npm.cmd test` and `npm.cmd run build:web`.
