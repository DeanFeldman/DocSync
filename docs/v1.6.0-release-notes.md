# DocSync v1.6.0 release notes

Released: 4 August 2026

DocSync v1.6.0 made reviewed document generation non-blocking and improved
custom Word list preservation.

## Background processing

- **Process** submits a durable editor operation and returns `202 Accepted`
  without waiting for DOCX generation.
- Jobs progress through queued, preparing documents, applying changes,
  validating files, saving versions, refreshing workspace, and completed or
  failed states.
- A workspace-level status indicator remains visible while users navigate to
  other documents and modes.
- Completion and failure notifications do not force the active editor block to
  change.
- Completion selectively refreshes affected document heads, version history,
  editor blocks, matches, search results, and download URLs.
- When a completed job produces a version newer than an unrelated active
  draft, DocSync offers **Open new version** or **Continue viewing current
  version**.

## Reliability and recovery

- A bounded local worker pool performs generation outside the request path.
- The database records status, stage, timestamps, source request, affected
  documents, result versions, and safe failure details.
- Normal operation uses short database transactions to reduce SQLite writer
  contention.
- Base-version validation still returns `409 Conflict` before any document head
  advances.
- Multi-document generation remains atomic; failed output is removed and no
  partial current version is exposed.
- A queued or processing operation found during restart is marked interrupted
  and can be retried from its original reviewed request.

## Word list styles

When the submitted list type matches the existing paragraph, DocSync preserves
the current custom or localised Word list style and updates only supported list
level metadata. Changing list type still requires a compatible Word list style
in the document.

## API additions

```text
POST /api/document-sets/{document_set_id}/editor-generate-async
GET  /api/editor-operations/{operation_id}
GET  /api/generation-jobs/{job_id}
GET  /api/generation-jobs
GET  /api/document-sets/{document_set_id}/generation-jobs
POST /api/generation-jobs/{job_id}/retry
```

Schema migration 3 adds durable `stage` and `updated_at` fields to editor
operations. Existing completed and failed rows are backfilled deterministically.

## Verification

The release was covered by API tests for immediate acceptance, progress,
conflicts, atomic rollback, interruption, retry, and draft safety; frontend
contract tests for persistent status and selective reconciliation; and a
production web build.
