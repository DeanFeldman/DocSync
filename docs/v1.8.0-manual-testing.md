# DocSync v1.8.0 manual testing

This is the release acceptance gate for real Microsoft Word layout behavior.
Automated tests do not replace this procedure. Record the Windows version,
Office version/build, document names, result, screenshots, generated DOCX, and
tester/date for each run.

## Test documents

Prepare at least two related DOCX files with five or more pages containing:

- headings, normal paragraphs, ordered and bullet lists;
- repeated wording and a long wrapped paragraph;
- a paragraph crossing a page boundary;
- tables and several paragraphs in one table cell;
- multiple sections, including portrait and landscape pages;
- default/first/even and linked headers and footers;
- a page-number field, logo, image, text box, and watermark.

Keep an untouched copy of every source file and its SHA-256 checksum.

## Preview and progressive readiness

1. Open the set, select a document and Layout, then choose **Load Word Preview**.
2. Confirm the action returns control within two seconds and normal navigation
   remains usable.
3. Confirm named stages progress without a blocking dialog.
4. Confirm the controlled PDF pages appear before selectable-text preparation
   completes.
5. Reopen the same immutable version and confirm the cache avoids another Word
   startup. Open another version and confirm it does not reuse the first PDF.
6. Force a Word failure (for example, an unresolved Word dialog), confirm Edit
   and structured Layout remain usable, close the cause, and retry successfully.

## Mapping and inline editing

1. Test hover, focus, Tab order, Enter, Space, mouse activation, zoom in/out,
   fit width/page, scrolling, window resize, and sidebar resize.
2. Confirm overlays stay aligned and repeated wording selects the intended
   immutable block. Ambiguous content must not guess.
3. Edit body, heading, list, table, header, and footer paragraphs. Confirm the
   cursor appears near the clicked point and the app stays in Layout.
4. Confirm Enter cannot create a paragraph and multiline paste becomes one
   paragraph. Confirm Escape closes inline typing and returns region focus.
5. Test bold, italic, underline, headings where valid, lists, indent/outdent,
   alignment, Undo, and Redo. Confirm sidebar and overlay stay synchronized.
6. Make a draft, select another block, and test both **Keep editing** and
   **Discard draft and continue**.
7. Confirm significantly longer text shows the draft-wrap warning and no UI
   claims final browser pagination.

## Matches, preview, and generation

1. Review exact matches and near-match score/differences in the Layout sidebar.
2. Confirm a near match cannot be targeted without explicit inclusion.
3. Exercise shared wording, per-document values, and whole-paragraph override.
4. Preview and confirm every intended document/location without leaving Layout.
5. Generate, continue navigating during processing, and confirm the new
   immutable version becomes current and receives a fresh Word preview/map.
6. Open the generated DOCX in Word. Confirm intended text/formatting, final
   wrapping and pagination, fields, images, text box, watermark, section
   orientation, tables, and linked headers/footers are correct.
7. Restore a prior version, then confirm the restoration creates another
   immutable version and renders its own preview.

## Theme, accessibility, and installer

1. Repeat representative selection/edit/error states in light and dark themes.
2. Complete the direct-selection workflow using only the keyboard and a screen
   reader; verify meaningful labels include page/type/table or header context.
3. Build the Windows installer, install into a clean test location, run the
   packaged-backend health smoke test, and repeat a preview/edit/generate cycle.

## Release evidence

The release may be marked manually passed only when all steps have evidence and
the generated documents were inspected in Microsoft Word. Do not infer this
status from automated tests or from a successful installer build.
This is the release-gate plan for Microsoft Word/PDF geometry and installed
desktop behaviour. Automated tests cannot prove visual overlay alignment in a
real Word-rendered document, so do not mark v1.8.0 accepted or create its tag
until every required row has a recorded result.

## Environment record

Record:

- tester and date;
- Windows edition/build and display scale;
- Microsoft Word version/bitness;
- DocSync installer filename and SHA-256;
- light/dark theme;
- monitor resolution;
- fixture filename and SHA-256.

## Required fixture

Prepare one DOCX containing at least:

- four pages and multiple sections;
- headings, body paragraphs, numbered and bullet lists;
- identical paragraph wording in two or more locations;
- a paragraph wrapping across several lines;
- a paragraph crossing a page boundary;
- two tables, including several rows and multiple paragraphs in one cell;
- default, first-page, even-page, and linked headers;
- a footer with ordinary editable wording and a page-number field;
- a logo, text box, watermark, and another unsupported object;
- different margins plus portrait and landscape sections.

Include short unique identifiers in each supported block so the exact Quill
target can be confirmed. Keep a pristine copy for repeat runs.

## Core acceptance procedure

For each supported fixture region, record Pass/Fail, page, expected block ID or
identifier, actual selected location, and notes.

1. Create a document set and open the fixture in Layout.
2. Confirm structured selection appears before Word is invoked.
3. Choose **Load Word Preview** and confirm the PDF becomes viewable before the
   direct-selection map reaches a terminal state.
4. Confirm queued/processing text is non-blocking and Edit/Compare/navigation
   remain usable.
5. Enable **Show selectable areas** and inspect every page.
6. Hover and focus mapped body, heading, list, table, header, and footer text.
7. Confirm each rectangle follows only its own rendered line(s) and does not
   cover unrelated text.
8. Select each supported kind with the mouse. Confirm the exact block opens in
   Edit, its location is correct, its Delta loads, and Quill receives focus.
9. Repeat activation with Tab/Shift+Tab and Enter, then with Space.
10. Confirm accessible names in the accessibility tree contain type, page,
    location, text preview, and state.
11. Select a linked header/footer occurrence on multiple pages. Confirm every
    occurrence opens the same physical block and Edit explains all linked
    sections.
12. Select both paragraphs from one table cell. Confirm table, row, column, and
    paragraph indexes differ as expected and the whole cell is not selected.
13. Select each region of the wrapped and cross-page paragraphs. Confirm every
    region opens the same block.
14. Confirm duplicate wording maps to the correct ordered occurrence. If the
    fixture is intentionally ambiguous, confirm no interactive overlay appears.
15. Focus read-only regions. Confirm the reason is announced and the editor does
    not open.

## Alignment matrix

Repeat page inspection and selection after each operation:

| Operation | Expected |
| --- | --- |
| Zoom out repeatedly | Regions remain on their text |
| Zoom in repeatedly | Regions remain on their text |
| Fit width | Page and regions fit together |
| Fit page | Full page and regions fit together |
| Horizontal scroll while zoomed | Regions move with the page |
| Vertical page scrolling | Correct page regions appear; distant pages unload |
| Resize narrow/wide | No coordinate drift |
| Collapse/expand sidebar | No coordinate drift |
| Windows display scaling used by target deployment | No coordinate drift |
| Light/dark theme | Controls, focus, status, and states remain readable |

Rotation must not be present on the controlled direct-selection surface.

## Draft and stale-version safety

1. Edit block A without generating, return to Layout, and select block B.
2. Confirm normal draft protection offers **Keep editing** and **Discard draft
   and continue**.
3. Confirm Keep editing preserves block A and its draft.
4. Repeat and discard; confirm block B opens and focuses.
5. Generate a reviewed edit. Confirm navigation remains available while the
   background job runs.
6. Confirm the new immutable version gets a different PDF/map render ID and old
   overlays cannot open it.
7. Restore an earlier version. Confirm the restored descendant gets its own
   preview/map and maps to its own element IDs.

## Partial and failure fallback

Use a fixture with complex/ambiguous text and, separately, simulate or inject a
map failure in a development workspace.

- Confirm reliable regions remain selectable in a partial map.
- Confirm unmapped content stays visible with no clickable overlay.
- Confirm a map failure leaves the Word PDF viewable.
- Confirm **Select from structure** remains available and opens exact blocks.
- Confirm Word unavailable/PDF failure returns to structured Layout and Edit
  continues to work without requesting overlays.

## Installed build and regression

1. Install `DocSync-Setup-1.8.0.exe` on a clean Windows user profile.
2. Confirm startup, `/api/health`, workspace creation, preview selection,
   processing, history, downloads, restart persistence, and uninstall.
3. Reopen an existing v1.7 workspace and repeat a body/table/header/footer edit.
4. Confirm original DOCX files remain unchanged by SHA-256.
5. Confirm no map/cache file is treated as authoritative document data.
