# DocSync v1.8.0 manual testing

This is the release acceptance gate for real Microsoft Word layout behavior.
Automated tests do not replace this procedure. Record the Windows version,
Office version/build, document names, result, screenshots, generated DOCX, and
tester/date for each run.

## Test documents

Prepare at least two related DOCX files with five or more pages containing:

- headings, normal paragraphs, ordered and bullet lists;
- repeated wording and a long wrapped paragraph;
- a paragraph crossing a page boundary;
- tables and several paragraphs in one table cell;
- multiple sections, including portrait and landscape pages;
- default/first/even and linked headers and footers;
- a page-number field, logo, image, text box, and watermark.

Keep an untouched copy of every source file and its SHA-256 checksum.

## Preview and progressive readiness

1. Open the set, select a document and Layout, then choose **Load Word Preview**.
2. Confirm the action returns control within two seconds and normal navigation
   remains usable.
3. Confirm named stages progress without a blocking dialog.
4. Confirm the controlled PDF pages appear before selectable-text preparation
   completes.
5. Reopen the same immutable version and confirm the cache avoids another Word
   startup. Open another version and confirm it does not reuse the first PDF.
6. Force a Word failure (for example, an unresolved Word dialog), confirm Edit
   and structured Layout remain usable, close the cause, and retry successfully.

## Mapping and inline editing

1. Test hover, focus, Tab order, Enter, Space, mouse activation, zoom in/out,
   fit width/page, scrolling, window resize, and sidebar resize.
2. Confirm overlays stay aligned and repeated wording selects the intended
   immutable block. Ambiguous content must not guess.
3. Edit body, heading, list, table, header, and footer paragraphs. Confirm the
   cursor appears near the clicked point and the app stays in Layout.
4. Confirm Enter cannot create a paragraph and multiline paste becomes one
   paragraph. Confirm Escape closes inline typing and returns region focus.
5. Test bold, italic, underline, headings where valid, lists, indent/outdent,
   alignment, Undo, and Redo. Confirm sidebar and overlay stay synchronized.
6. Make a draft, select another block, and test both **Keep editing** and
   **Discard draft and continue**.
7. Confirm significantly longer text shows the draft-wrap warning and no UI
   claims final browser pagination.

## Matches, preview, and generation

1. Review exact matches and near-match score/differences in the Layout sidebar.
2. Confirm a near match cannot be targeted without explicit inclusion.
3. Exercise shared wording, per-document values, and whole-paragraph override.
4. Preview and confirm every intended document/location without leaving Layout.
5. Generate, continue navigating during processing, and confirm the new
   immutable version becomes current and receives a fresh Word preview/map.
6. Open the generated DOCX in Word. Confirm intended text/formatting, final
   wrapping and pagination, fields, images, text box, watermark, section
   orientation, tables, and linked headers/footers are correct.
7. Restore a prior version, then confirm the restoration creates another
   immutable version and renders its own preview.

## Theme, accessibility, and installer

1. Repeat representative selection/edit/error states in light and dark themes.
2. Complete the direct-selection workflow using only the keyboard and a screen
   reader; verify meaningful labels include page/type/table or header context.
3. Build the Windows installer, install into a clean test location, run the
   packaged-backend health smoke test, and repeat a preview/edit/generate cycle.

## Release evidence

The release may be marked manually passed only when all steps have evidence and
the generated documents were inspected in Microsoft Word. Do not infer this
status from automated tests or from a successful installer build.
