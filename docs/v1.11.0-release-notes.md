# DocSync v1.11.0 release notes

## Batch editing and exhaustive Find & Replace

DocSync v1.11.0 adds review-first workspace Find & Replace and durable pending
batches. Users can combine multiple independent replacements with reviewed rich
editor changes, inspect or disable individual occurrences, resolve conflicts,
and apply the complete batch once.

Every affected document is opened and generated once per batch, producing at
most one new immutable version regardless of how many approved operations target
that document. All output packages are staged and validated before the database
transaction advances any document head. A failure leaves the entire logical
batch uncommitted.

## Complete Word text inventory

The new direct OOXML inventory separates text discovery from editability. Logical
segments concatenate visible text across runs, bookmarks, hyperlinks, content
controls, and revision markup while retaining exact character-to-node mappings.
This makes phrases split across formatting runs searchable and replaceable
without flattening or reconstructing the document.

Coverage includes body paragraphs, headings, lists, top-level and nested tables,
default/first/even headers and footers, hyperlinks, footnotes, endnotes, comments,
content controls, WordprocessingML/VML text boxes, fields, tracked insertions and
deletions, and DrawingML text. Linked physical header/footer parts are
deduplicated.

Text that is discovered but cannot be modified safely remains visible with an
explicit read-only reason. Field instructions/results, tracked deletions, and
DrawingML text are protected by default. Matches crossing protected fields,
special characters, hyperlink/control boundaries, or revision boundaries are
rejected before write-back.

## Safe cross-run replacement

Each search result records its immutable version, OOXML part, stable segment,
logical range, and expected source text. Replacement compilation revalidates
these values and rejects stale, duplicate, overlapping, or protected targets.
Node edits run in descending offset order. A replacement spanning several runs
inherits the first matched run's formatting; unaffected text, relationships,
styles, numbering, media, embedded parts, bookmarks, and metadata remain intact.

Unicode NFKC normalization, case folding, whitespace normalization, punctuation,
one-character searches, and Unicode-aware whole-word matching retain mappings to
the original logical offsets. FTS5 remains a candidate-order accelerator but can
never exclude a document from the authoritative package scan.

## Durable batches and history

Additive schema migration 8 stores ordered batch operations and occurrence-level
selection/audit records while preserving the existing `EditorOperation` version
lineage and background-job model. Drafts survive restart, generation reports
document progress, and completed batches appear in history with operation,
document, occurrence, and resulting-version details.

## Verification and performance

The exhaustive fixture contains 28 known occurrences of one distinctive phrase
across ordinary and complex Word structures. DocSync reports exactly 28 when
comments and historical tracked text are included, and exactly 26 in the default
visible search. Cross-run replacements are reopened and rescanned, while
unchanged relationships, styles, and numbering are checksum-verified.

The automated release gate contains 80 Python/API tests and 42 Node/Desktop
tests, frontend production compilation, the frozen Windows backend build, its
health smoke test, and installer packaging. Microsoft Word 16.0 opened the
original and generated acceptance fixtures without repair prompts while retaining
tables, nested tables, hyperlinks, notes, comments, fields, content controls,
inline shapes, revisions, and sections.

On the recorded Windows benchmark, scanning 50,000 logical segments took an
811.98 ms median, compiling 5,000 replacement patches took 9.05 ms, and applying
ten edits to each of ten packages in one batch was 9.83 times faster at the
package boundary than repeated one-edit regeneration.

See the [architecture and support matrix](batch-find-replace-text-inventory.md),
[measured performance evidence](evidence/v1.11.0-batch-find-replace-performance.md),
and [manual acceptance plan](v1.11.0-manual-testing.md).

## Known boundaries

Field results and instructions, tracked deletions, and DrawingML text remain
read-only. Cached chart values, equation text, embedded OLE contents, external
linked documents, and vendor-specific/custom XML text are not currently promoted
to editable inventory segments. The detailed support matrix is authoritative and
does not represent these structures as editable.
