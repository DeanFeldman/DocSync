# DocSync v1.4.1 release notes

DocSync v1.4.1 is a focused workspace-loading performance release. It makes the
workspace shell and tab selection immediate while expensive, version-specific
resources load only when their view needs them.

## Faster workspace opening

- The client commits document-set metadata, the file list, and the active
  document header before requesting the first structured editor resource.
- A failed first-document request leaves the created workspace open so another
  document can still be selected.
- Creation displays named upload, validation, editor-preparation, and
  workspace-opening stages.
- Upload processing validates each package and constructs each `python-docx`
  object model once. That parsed object is reused for element extraction and
  initial editor revisions.
- New records and block revisions are collected and flushed in batches while
  the existing transaction and filesystem rollback behavior remain intact.
- The create endpoint emits local `Server-Timing` values for upload,
  validation, parsing, persistence, exact-match setup, serialization, and the
  total request.

## Lazy views and version-aware caching

- Editor content is cached by immutable document-version ID.
- In-flight loads are deduplicated by resource key and stale results are
  ignored when the active document changes.
- Layout opens with the cached structured document. It never starts Microsoft
  Word rendering merely because the tab was selected.
- High-fidelity Word rendering starts only from **Load Word Preview**. A
  successful PDF is reused for the same immutable version, while a failed
  render can be retried without blocking Edit.
- Exact matches remain available to the editor, while near-match discovery
  starts only after Compare becomes active.
- The near-match response supplies its final score, decision, and difference
  spans directly; the client no longer follows it with a duplicate comparison
  request.
- Version history is requested only when its disclosure control is opened.
- View selection, block selection, draft state, and per-view scroll positions
  are retained by document version.
- Resource and view-state caches are bounded with least-recently-used eviction
  and are cleared precisely when a document or set is deleted.

## Large documents

- Editor block cards are memoized.
- The Edit list initially mounts 200 blocks and progressively adds further
  batches during scrolling or through the explicit **Show next** control.
- Search navigation expands the mounted range when its target lies beyond the
  current batch.

## Safety and compatibility

- Existing DOCX extension, package, encryption, decompression, and parser
  checks remain active.
- Creation remains transactional and removes partially written original files
  on failure.
- Original uploads remain immutable; confirmed changes and restores still
  produce new immutable versions.
- Existing SQLite workspaces continue to use the startup backfill and require
  no manual migration.
- No external telemetry, network cache, API key, or cloud service was added.

## Verification

- Production React/TypeScript build.
- Node contract tests for shell-first opening, lazy resources, LRU caching, and
  progressive block rendering.
- Backend tests for one-pass parsed-document reuse, stage timing, structured
  endpoints that do not render Word, upload safety, editing, restoration,
  backups, and storage behavior.

The local Standard benchmark measured an 89.85% median improvement over the
pre-change baseline. See
[the performance evidence](evidence/v1.4.1-performance.md). The packaged
Windows installer still requires its release smoke test before the tag is
published.
