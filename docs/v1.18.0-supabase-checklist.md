# v1.18.0 Supabase and release checklist

Do not paste secrets into source control, CI logs, renderer code, or this file.

1. In the Supabase SQL Editor run `analytics/supabase-v1.18-cloud-schema.sql`.
   It creates the `devices`, `workspace_snapshots`, and workspace-head metadata,
   owner-scoped RLS policies, and the atomic promotion RPC.
2. Confirm the `docsync-workspaces` Storage bucket is **private**. Verify with
   two ordinary accounts that neither can list, read, or upload objects under
   the other's `users/<uuid>/snapshots/` prefix. Verify metadata queries and
   promotion are equally owner-scoped; an admin application role must not grant
   access to user archives.
3. Deploy the public completion page:
   `supabase functions deploy docsync-auth-complete --no-verify-jwt`.
   Confirm the function has public invocation enabled and that its strict CSP
   permits only its inline completion script and style.
4. Add `https://<project-ref>.supabase.co/functions/v1/docsync-auth-complete`
   to **Authentication > URL Configuration > Redirect URLs**. Google continues
   to redirect through Supabase's `/auth/v1/callback`; do not register the
   desktop custom protocol with Google.
5. Create GitHub **Repository Variables** `VITE_SUPABASE_URL` and
   `VITE_SUPABASE_PUBLISHABLE_KEY`. These are public compile-time values used by
   the desktop renderer and release workflow. Optionally set public
   `VITE_AUTH_COMPLETION_URL` only for an equivalent HTTPS completion endpoint.
6. Keep `SUPABASE_SECRET_KEY`, service-role credentials, Google client secrets,
   and any analytics-only secrets in GitHub **Repository Secrets** only. The
   release workflow must never pass them to Vite, Electron renderer code, or the
   Python document backend.
7. Before tagging, run the manual guide, verify a package build embeds the
   configured project URL, and inspect the release workflow variables. The
   release workflow fails closed when its two required Vite repository variables
   are absent.
